Run all commands from the extracted code-a3 directory.
Tested: Ubuntu/Linux, Python 3.12.3, OVS 3.3.9, Ryu 4.34, iperf 2.1.9.
sudo apt install mininet openvswitch-switch iperf python3-venv
python3 -m venv .venv
.venv/bin/pip install 'setuptools==67.6.1' wheel
.venv/bin/pip install -r requirements.txt
sudo systemctl start openvswitch-switch
sudo python3 experiments/run.py "$PWD/.venv/bin/ryu-manager"
Results overwrite results/*.txt and results/*-controller.log.

Individual runs (use separate terminals; stop Mininet and controller between runs):
.venv/bin/ryu-manager --ofp-tcp-listen-port 6633 p1/reactive.py
sudo python3 p1_topo.py
Replace reactive.py with proactive.py for proactive forwarding.
For Parts 2/3 use sudo python3 p3_topo.py and one of:
.venv/bin/ryu-manager --ofp-tcp-listen-port 6633 p2/routing.py
DELAY12=40 .venv/bin/ryu-manager --ofp-tcp-listen-port 6633 p2/routing.py
CONGESTION=1 .venv/bin/ryu-manager --ofp-tcp-listen-port 6633 p2/routing.py
Inside Mininet: pingall; h1 ping -c 10 h3
Inspect: sh ovs-ofctl -O OpenFlow13 dump-flows s1
Cleanup after interrupted runs: sudo mn -c

The supplied topology files are unchanged. Controllers assume their exact host
MAC addresses, attachment ports and switch links. autoSetMacs=True is required.
The p2/graph.py file is the original illustrative graph calculation; actual
OpenFlow forwarding is implemented in p2/routing.py, shared by Parts 2 and 3.
The bundled Ryu wheel is third-party software (Apache 2.0), not student work.
Its existing compatibility modification uses getattr for eventlet's removed
ALREADY_HANDLED symbol. Dependencies are downloaded by pip; no external local
source directory is required. Report generation additionally needs reportlab.
